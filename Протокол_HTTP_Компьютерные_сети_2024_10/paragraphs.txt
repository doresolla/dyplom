Привет, я Андрей Сазыкин, это курс компьютерной сети тема лекции протокол HTTP. Мы начинаем рассматривать протоколы прикладного уровня, стека протоколов TCP/IP и начнем с протокола HTTP. HTTP расшифровывается как Hypertext Transfer Protocol, протокол передачи гипертекста. И протокол HTTP – это основа веб. В целом, концепцию веб-п предложил Тим Бернесли из CERN достаточно давно в 1989 году. 
 Тим Бернесли предложил четыре вещи. Первое – язык гипертекстовой разметки страниц HTML, гипертекст markup language, протокол передачи гипертекстовых страниц HTTP. Веб-сервер, с которыми размещаются страницы в формате HTML и текстовый веб-браузер, который может подключаться к разным веб-серверам и показывать страницы с разных веб-серверов. 
 В варианте Тим Бернесли браузер показывал только текст. Понятно, что сейчас веб-браузеры позволяют показывать изображения, видео, музыку и много других типов ресурсов. Что такое гипертекст. Это текст, в который включена разметка. И разметка говорит, как обрабатывать тот или иной фрагмент текста. В веб используется разметка HTML, гипертекст markup language, указывается так называемые теги. Теги могут указывать форматирование. Например, протокол HTTP – это заголовок. Тег H1, теги UL и I позволяют указать список. Также теги позволяют вставлять в странице так называемые гиперсылки. По гиперсылке можно перейти с одной веб-страницы на другую. Именно легкая связность страниц и обеспечила такую популярность вебу. Вот таким образом выглядит веб-страница, когда ее показывает браузер. 
 Заголовок протокол HTTP – список. В важную роль веб играет URL. Форма ресурс – локатор или единообразный определитель местонахождения ресурса. Именно по URL определяется, где именно находится страница. Именно URL вставляются в гиперсылки и позволяют связать одну страницу с другими страницами. URL состоит из нескольких частей. 
 Сейчас мы рассмотрим три основные части. Первое – это протокол. Здесь в примере указывается протокол HTTP. Вторая – адрес сервера, на котором размещается страница. Здесь может быть доменное имя. Например, адрес моего сайта также может использоваться IP-адрес. 
 И третья часть – это адрес той страницы, которую мы хотим загрузить с сервера. Кроме протокола HTTP в URL могут использоваться другие протоколы, например, протокол HTTPS, протокол FTP и большое количество других. Также не обязательно в URL и в целом в HTTP использовать только HTML страницы. 
 Можно использовать URL для текстовых файлов, файлов с картинками, файлов с видео и других типов файлов. Есть несколько версий протокола HTTP. Самая первая версия 0.9 – экспериментальная версия, которая использовалась только внутри CERN. Ее создали в 1991 году. Первая официальная версия HTTP.1 вышла в 1996 году. И почти сразу в 1997 году вышло расширение этой версии HTTP.1.1. В эту версию по сравнению с первой версией HTTP было добавлено каширование, работа с постоянным соединением и аутентификацией. Но именно эта версия чаще всего используется сейчас. Хотя сейчас есть уже две другие более современные версии. Обновленная версия протокола HTTP.2 вышла в 2015 году. Она обеспечила повышение производительности и безопасности. 
 Современная версия HTTP.3 вышла в 2022 году и сейчас постепенно вводится в эксплуатацию. Протокол HTTP работает в режиме запрос ответ клиент. Как правило, это web-браузер отправляет запрос на сервер, как правило, запрос на какую-либо страницу. И сервер отправляет ответ, который содержит именно то страницу, которую запросил браузер. На транспортном уровне протокола HTTP используют протоколу TCP. 
 Это означает, что для HTTP гарантирована надежная доставка данных. И веб-серверы используют порт 80 TCP. Протокол HTTP.1.1 и более ранние версии используют текстовые режимы работы, а HTTP.2 и HTTP.3 – более сложный, бинарный режим. 
 В этом видео мы рассмотрим, как работают HTTP первой версии и версии 1.1, как работают версии HTTP.2 и 3. Мы рассмотрим более подробно, далее в курсе. Текстовый режим работы означает, что браузер и сервер предают друг другу самые обычные строки. Запрос HTTP состоит из трех частей. Первая часть сам запрос, вторая часть заголовки и третья часть телообщения. Заголовки и телообщения не обязательно. 
 Запрос состоит из трех частей. Первая часть – это так называемый метод HTTP. Здесь указан метод GET – получить ресурс. После метода указывается, какой именно ресурс мы хотим получить. 
 Здесь мы хотим получить страницу /courses. И третья часть запроса – это используемая версия протокола HTTP. Здесь мы используем версию HTTP.1.1. Страки запроса можно указывать заголовки. Они являются не обязательным. Единственное исключение – заголовок host, который является обязательным в HTTP версии 1.1. Заголовок host содержит доменное имя веб-сервера, к которому мы подключаемся. 
 Зачем это сделано. Дело в том, что современные серверы на одном и том же IP-адресе могут обслуживать несколько веб-серверов с разными доменными именами. И для того, чтобы определиться, какому именно доменному имени направлен запрос, нужно добавлять заголовок. Заголовки в HTTP также в текстовом режиме. Сначала указывается название заголовка, заголовок host, дальше двои точки, пробел и после этого значения. Ассозыгин.ру – доменное имя сервера, к которому мы хотим обратиться. 
 Здесь указано в качестве примера доменное имя на его сервер. Но и тело сообщения его не обязательно указывать в запросе. Кроме метода GET в HTTP можно использовать другие методы. Веб-сервер в зависимости от того, какой метод в запросе HTTP он получил, будет выполнять разные действия. Метод GET означает, что клиент запрашивает веб-страницу сервера. Не обязательно веб-страницу, это может быть какой-нибудь другой ресурс. Метод POST означает, что клиент передает какие-то данные на веб-сервер. Метод GET голова запрашивает не всю страницу, а только ее заголовок. Метод PUT используется для того, чтобы поместить страницу на веб-сервер. 
 Метод DELETE для того, чтобы удалить страницу с веб-сервера. Метод OPTIONS запрашивает список всех поддерживаемых методов, которые может обслуживать интересующий веб-сервер. Кроме тех методов, которые перечислены, есть другие методы HTTP. 
 Следует отметить, что на практике чаще всего используются методы GET, запрос веб-страницы или другого ресурса и POST, передача данных на веб-сервер. Ответ HTTP, который сервер отправляет клиенту, состоит из трех частей. Статус ответа, заголовки, которые являются необязательными и тело сообщения. Статус ответа говорит о том, как был запрос. 
 200 уК запрос выполнен успешно. Заголовки в том же формате, как и в запросе, название заголовка, контентайп, тип, передаваемых данных, тип контента, значение текста HTML, текст формате HTML, кодировка у TF 8 и длина сообщения. После этого в теле сообщения передается запрашиваемая HTML страница. Какие могут быть статусы ответов HTTP. Статус это треузначное число, статусы сгруппированы в 5 групп. 
 И группа опреляется по первой цифре в числе. Статусы, которые начинаются на единицу, это информационные статусы. Статусы, которые начинаются на двойку, говорят об успешном выполнении запроса. 
 Например, статус 200 уК. Статусы, которые начинаются на тройку, говорят о перенаправлении. Например, 301 постоянное перемещение говорит о том, что страница была перемещена по другому адресу. И в ответе указывается новый адрес страницы 302-временное перенаправление. 
 Говорит о том, что страница тоже была перемещена, но не постоянно, а временно. Статусы, которые начинаются на 4, говорят о том, что произошла ошибка на стороне клиент. Например, 403 доступ запрещен. Клиент пытается обратиться к ресурсу, для которого нет прав доступа. 404 страница не найдена, клиент обращается к странице, который нет на сервере. Статусы, которые начинаются на 5, говорят об ошибке, но уже на стороне сервер. Например, 500 внутренняя ошибка сервера произошла какая-то проблема в работе программного обеспечения веб-сервера. 501 метод нереализован в запросе, использован такой метод HTTP, который веб-сервер обработать не может. 
 Ну и также есть большое количество других статусов, которые разделены на эти 5 групп. Давайте рассмотрим короткий пример. У нас в курсе будет отдельное видео, где мы будем отправлять запросы HTTP в текстовом режиме и получать ответы. На первом этапе нужно подключиться по TCP к порту 80 нужного нам веб-сервера. Специально для курса я создал веб-сервер Network Surcourse. 
 Сейчас большая часть веб-серверов в интернет используют зачищенный протокол HTTPS. Мы подключились к этому серверу по протоколу TCP к порту 80 и после этого передаем обычные строки. 
 Первая строка — это запрос, метод GET. Мы хотим получить страницу. После этого указываем страницу /. Это корень сервера, просто корневую страницу. И версия протокола HTTP 1.1. Если у нас используется версия протокола HTTP 1.1, нам нужно обязательно использовать заглок host, к какому именно веб-серверу, с каким доменным именем мы обращаемся.  Сначала ответ, версия протокола HTTP 1.1, статус 200OK. Запрос обработан успешно. Дальше идут три заголовка. Первый заголовок сервер — это тип web-сервера. GetHub.com.  Вот так она выглядит. Итак, мы рассмотрели протокол HTTP, протокол передачи гипертекста. Это протокол, который часто используется на практике, основа World Wide Web. HTTP работает в режиме запрос-ответ. Клиент передает на сервер запрос, в котором указывает, что он хочет сделать. Есть несколько методов HTTP, чаще всего используются методы Get, получить страницу и пост. 
 Отправить какие-то данные на сервер, например те данные, которые пользователь вёл в форму. Сервер отправляет ответ, в котором указывается статус, например 200UK, запрос обработан успешно и передается сама HTML страница. Мы рассмотрели, как работает протокол версии 1.1 в текстовом режиме. 
 Более сложные версии используют бинарный режим. Почему это нужно. Дело в том, что современный веб более сложный, чем тот, который придумал TeamBurness.ly. Веб-страницы содержат не один файл с текстом, а кроме самой веб-страницы есть большое количество других файлов, картинок, видеотаблиц-стили CSS, кода на JavaScript. 
 Для того, чтобы показать одну страницу, клиенту нужно загрузить все эти файлы сервера. Кроме этого, часто на практике веб-серверы вместо статических страниц используют программы, которые генерируют такие страницы динамически. Для того, чтобы лучше работать с такими данными, разработаны новые версии протокола HTTP/2 и HTTP/3, они позволяют загружать страницы, которые содержат большое количество ресурсов быстрее, чем протокола HTTP версия 1.
