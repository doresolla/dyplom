HTTP расшифровывается как Hypertext Transware Protocol, протокол передачи гипертекста. И протокол HTTP – это основа веб. В целом концепцию веб-IP предложил Тим Бернесли из CERN достаточно давно в 1989 году. Тим Бернесли предложил четыре вещи. Первое – язык гипертекстовой разметки страниц HTML, гипертекст markup language, протокол передачи гипертекстовых страниц HTTP. Именно этот протокол мы сейчас и будем рассматривать веб-сервер, сервер, на котором размещаются страницы в формате HTML и текстовый веб-браузер, который может подключаться к разным веб-серверам и показывать страницы с разных веб-серверов. В варианте Тим Бернесли браузер показывал только текст. Понятно, что сейчас веб-браузеры позволяют показывать изображения, видео, музыку и много других типов ресурсов. Что такое гипертекст? Это текст, в который включена разметка. И разметка говорит, как показывать или обрабатывать тот или иной фрагмент текста. В веб используется разметка HTML, гипертекст марка plain language, указывается так называемой теги. Теги могут указывать форматирование. Например, протокол HTTP – это заголовок. Тег H1, теги UL и I позволяют указать список. Также теги позволяют вставлять в странице так называемые гиперсылки. По гиперсылке можно спереть из одной веб-страницы на другую. Именно легкая связность страниц и обеспечила такую популярность вебу. Вот таким образом выглядит веб-страница, когда ее показывает браузер. Заголовок протокол HTTP – список. В важную роль веб играет URL – Uniform Resource Locator или енообразный определитель местонахождения ресурса. Именно по URL определяется, где именно находится страница. Именно URL вставляются в гиперсылки и позволяют связать одну страницу с другими страницами. URL состоит из нескольких частей. Сейчас мы рассмотрим три основные части. Первое – это протокол. Здесь в примере указывается протокол HTTP. Вторая – это адрес сервера, на котором размещается страница. Здесь может быть доменное имя. Например, адрес моего сайта также может использоваться IP адрес. И третья часть – это адрес той страницы, которую мы хотим загрузить с сервера. Кроме протокола HTTP в URL могут использоваться другие протоколы. Например, протокол HTTPS, протокол FTP и большое количество других. Также не обязательно в URL и в HTTP использовать только HTML страницы. Можно использовать URL для текстовых файлов, файлов с картинками, файлов с видео и других типов файлов. Есть несколько версий протокола HTTP. Самая первая версия 0.9 – это экспериментальная версия, которая использовалась только внутри CERN. Ее создали в 1991 году. Первая официальная версия HTTP.1 вышла в 1996 году. И почти сразу в 1997 году вышло расширение этой версии HTTP.1.1. В эту версию, по сравнению с первой версией HTTP, было добавлено каширование, работа с постоянным соединением и аутентификацией. Но именно эта версия чаще всего используется сейчас. Хотя сейчас есть уже две другие более современные версии, обновленная версия протокола HTTP.2 вышла в 1996 году.
 в 2015 году, она обеспечила повышение производительности и безопасности. Современная версия HTTP – HTTP-3 вышла в 2022 году и сейчас постепенно вводится в эксплуатацию. Протокол HTTP работает в режиме запрос ответ. Клиент как правило веб-браузер, отправляет запрос на сервер, как правило запрос на какую-либо страницу. И сервер отправляет ответ, который содержит именно то страницу, которую запросил браузер. На транспортном уровне протокола HTTP используют протоколу TCP. Это означает, что для HTTP гарантирована надежная доставка данных. И веб-серверы используют порт 80 TCP. Протокол HTTP-1.1 и более ранней версии используют текстовый режим работы, а HTTP-2 и HTTP-3 – более сложный, бинарный режим. В этом видео мы рассмотрим, как работают HTTP первой версии и версии 1.1, как работают версии HTTP-2.3. Мы рассмотрим более подробно, далее в курсе. Текстовый режим работы означает, что браузер и сервер предают друг другу самые обычные строки. Запрос HTTP состоит из трех частей. Первая часть сам запрос, вторая часть заголовки и третья часть телообщения. Заголовки и телообщения не обязательно. Запрос состоит из трех частей. Первая часть – это так называемый метод HTTP. Здесь указан метод GET – получить ресурс. После метода указывается, какой именно ресурс мы хотим получить. Здесь мы хотим получить страницу slash-courses. И третья часть запроса – это используемая версия протокола HTTP. Здесь мы используем версию HTTP-1.1. Страки запроса можно указывать заголовки. Они являются не обязательным. Единственное исключение – это заголовок host, который является обязательным в HTTP версии 1.1. Заголовок host содержит доменное имя веб-сервера, к которому мы подключаемся. Зачем это сделано? Дело в том, что современные серверы на одном и том же IP-адресе могут обслуживать несколько веб-серверов с разными доменными именами. И для того, чтобы определиться, к какому именно доменному имени направлен запрос, нужно добавлять заголовок. Заголовки в HTTP также в текстовом режиме. Сначала указывается название заголовка, заголовок host, дальше двоиточие, пробел и после этого значения. Asus.roo – доменное имя сервера, к которому мы хотим обратиться. Здесь указано в качестве примера доменное имя на его серверах. И тело сообщения его не обязательно указывать в запросе. Кроме метода get в HTTP можно использовать другие методы. WebServer в зависимости от того, какой метод в запросе HTTP он получил, будет выполнять разные действия. Metod get означает, что клиент запрашивает веб-страницу сервера. Не обязательно веб-страницу, это может быть какой-нибудь другой ресурс. MetodPost означает, что клиент передает какие-то данные на web-сервер. MetodGet в голова запрашивает не всю страницу, а только ее заголовок. MetodPost используется для того, чтобы поместить страницу на web-сервер. Метод delete для того, чтобы удалить страницу с web-сервера. MetodOptions запрашивает список всех поддерживаемых методов, которые может обслуживать интересующий web-сервер. Кроме тех методов, которые перечислены, есть другие методы HTTP. Следует отметить, что на практике чаще всего используются методы get, запрос веб-страницы или другого ресурса и пост. Передача данных на web-сервер. Ответ HTTP, который сервер отправляет клиенту, состоит
 из трех частей. Статус ответа, заголовки, которые являются необязательными и тело сообщения. Статус ответа говорит о том, как был запрос. 200 уК запрос выполнен успешно. Заголовки в том же формате, как и в запросе. Название заголовка, контентайп, тип. Передаваемых данных, тип контента, значения текста HTML, текст формате HTML, кодировка уТФ-8 и длина сообщения. После этого в теле сообщения передается запрашиваемая HTML страница. Какие могут быть статусы ответов HTTP? Статус это трозначное число, статусы сгруппированы в 5 групп. И группа опреляется по первой цифре в числе. Статусы, которые начинаются на единицу, это информационные статусы. Статусы, которые начинаются на двойку говорят об успешном выполнении запроса. Например, статус 200 уК. Статусы, которые начинаются на тройку говорят о перенаправлении. Например, 301 постоянное перемещение говорит о том, что страница была перемещена по другому адресу. И в ответе указывается новый адрес страницы 302 временное перенаправление. Говорит о том, что страница тоже была перемещена, но не постоянно, а временно. Статусы, которые начинаются на 4, говорят о том, что произошла ошибка на стороне клиент. Например, 403 доступ запрещен, клиент пытается обратиться к ресурсу, для которого у нет прав доступа. 404 страница не найдена, клиент обращается к странице, который нет на сервере. Статусы, которые начинаются на пять говорят об ошибке, но уже на стороне сервер. Например, 500 внутренняя ошибка сервера произошла какая-то проблема в работе программного обеспечения веб-сервера. 501 метод не реализован в запросе, использован такой метод HTTP, который веб-сервер обработать не может.
