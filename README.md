# Django веб-приложение для автоматического конспектирования видеолекций

Это каркас локального Django-приложения под проект **«Автоматическое конспектирование видеолекций»**.

Реализовано:

- регистрация и вход пользователя;
- загрузка видеофайла пользователем;
- запуск тяжелого ML-пайплайна в фоне через Celery;
- личный кабинет пользователя;
- общая открытая база готовых конспектов;
- уведомления в личном кабинете;
- отправка email после завершения обработки;
- оценивание результата: рейтинг 1–5 и текстовый отзыв;
- преобразование markdown-конспекта в PDF с сохранением изображений;
- просмотр итогового PDF-конспекта прямо в личном кабинете;
- хранение статуса, прогресса, логов обработки и ошибок.



## Быстрый запуск локально

```bash
python -m venv .venv
.venv\Scripts\activate  # Windows
# source .venv/bin/activate  # Linux/macOS

pip install -r requirements.txt
copy .env.example .env  # Windows
# cp .env.example .env  # Linux/macOS

python manage.py migrate
python manage.py createsuperuser
```

```bash
docker compose up -d redis
```

В одном терминале:

```bash
python manage.py runserver
```

Во втором терминале:

```bash
celery -A config worker -l info --pool=solo
```

Для Linux можно использовать многопроцессный режим:

```bash
celery -A config worker -l info --concurrency=2
```

На Windows для тяжелых ML-задач обычно стабильнее `--pool=solo`, но параллельную обработку можно вынести в несколько отдельных воркеров.


## Структура проекта

```text
config/                 настройки Django и Celery
summaries/              основное приложение
summaries/services/     адаптер полного ML-пайплайна
summaries/templates/    HTML-шаблоны
media/                  загруженные видео и результаты обработки
```

## Основные страницы

- `/` — общая база конспектов;
- `/upload/` — загрузка видео;
- `/dashboard/` — личный кабинет;
- `/notes/<id>/` — просмотр карточки обработки, готового конспекта и оценивание;
- `/notifications/` — уведомления пользователя;
- `/accounts/register/` — регистрация нового пользователя;
- `/accounts/login/` — вход;
- `/accounts/logout/` — выход.

## Важное замечание

Django-request не должен выполнять ASR, OCR, извлечение кадров и LLM-суммаризацию напрямую. Поэтому весь пайплайн запускается в `summaries/tasks.py` как Celery-задача. Это позволяет обрабатывать несколько видео без зависания веб-интерфейса.
